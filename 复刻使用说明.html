⑤ 部署步骤

5.1 配置 Secrets（名称一字不差）

Secret 名称填入内容说明
EMAIL_USER你的 163 邮箱地址发件人，例如 xxx@163.com
EMAIL_AUTH_CODE163 邮箱的 16 位授权码不是登录密码，在邮箱「设置→POP3/SMTP」里开启并获取
EMAIL_TO收件人邮箱，多个用逗号例如 2568974439@qq.com,2089178729@qq.com
LLM_API_KEY大模型 API Key用于生成时政 / 申论论证素材（缺了会走静态兜底）
LLM_BASE_URL大模型接口地址如 https://api.deepseek.com（不含 /v1）
LLM_MODEL模型名如 deepseek-v4-flash

5.2 配置腾讯云 SCF 定时器（两个）

读取本文件夹 scf_trigger.py，按其逻辑在腾讯云 SCF 建两个函数 / 触发器：

kaogong-morning：定时触发 Cron = 0 0 7 * * * *（每天北京时间 07:00），dispatch 的 inputs.mode = morning
kaogong-evening：定时触发 Cron = 0 0 22 * * * *（每天北京时间 22:00），dispatch 的 inputs.mode = evening
⚠️ 腾讯云 Cron 是 7 位（秒 分 时 日 月 周 年），第一位 0 是秒。若改用 GitHub 自带定时（daily.yml 里已预留 schedule 段），Cron 用 UTC，北京时间要减 8 小时（07:00→23:00 前一天）。

5.3 手动测试

在 GitHub 仓库 Actions 页找到 daily 工作流，点 Run workflow，mode 填 morning，确认收到一封「【考公每日加油站】… 距离国考还剩 X 天」的早间邮件即成功。

⑦ 常见问题

Q1：收不到邮件？
检查 163 授权码是否过期（重开 SMTP 获取新码）、EMAIL_TO 是否填错、GitHub Actions 运行是否 success。先手动 Run workflow 看日志。

Q2：定时不运行？
确认 SCF 触发器状态为「已启用」、Cron 为 7 位；或改用 GitHub schedule（注意 UTC）。查看 SCF 与 Actions 运行记录。

Q3：授权码报错（535）？
说明填的是登录密码而非 16 位授权码，去邮箱「设置→账户→POP3/SMTP 服务」开启并复制授权码，更新 EMAIL_AUTH_CODE 密钥。

Q4：AI 内容变成固定素材？
是 LLM 密钥未生效走了兜底，检查 LLM_API_KEY / LLM_BASE_URL / LLM_MODEL 三个密钥是否填对。
